# Roof Visualizer 3D — контекст проекта

3D-примерка кровли для продавцов кровельных материалов (металлочерепица, профнастил, фальц).
Клиент выбирает форму крыши, материал, цвет RAL, крутит дом, меняет размеры и видит результат.

**Только визуализация.** Никаких расчётов, смет, цен, раскладки листов — это сознательно вынесено за рамки проекта.
Не добавлять площади/метражи в UI без прямой просьбы.

Язык интерфейса — русский. Общение с владельцем — на русском.

## Текущее состояние

Рабочий прототип: `prototype/index.html` — один HTML-файл, Three.js r160 через importmap с jsDelivr, без сборки.
Открывается двойным кликом или любым статик-сервером (`npx serve prototype`).
Опубликован как артефакт claude.ai — https://claude.ai/artifact/ADxbz4V51N1asU6nmyXqwc

### Что уже умеет
- 5 форм крыши: односкатная (1), двускатная (2), вальмовая (4), шатровая (4), ломаная/мансардная (4)
- Параметры: ширина, длина, высота стен, угол ската (10–55°), свес
- Материалы: объёмная металлочерепица (приближённый профиль), профнастил (НС35-подобный) и фальц (процедурный шейдер)
- Покрытия: глянец / пурал / матовый (roughness + metalness)
- 14 цветов RAL
- Доборка: коньки и рёбра, торцевые и карнизные планки, трубчатые снегозадержатели с кронштейнами
- Водосток: желоба, воронки, трубы с коленами и хомутами; отдельный цвет (в цвет кровли / белый / коричневый / графит)
- Мансардные окна 78×118: 0–3 на скат, перетаскивание мышью или пальцем по скату; ставятся только на крупные скаты, автоматически уменьшают количество, если не помещаются
- Фасад: штукатурка 5 цветов, кирпич 3 цвета, камень 2 (процедурно в шейдере), цоколь 4 цвета, окна/двери 3 цвета
- Окна и дверь с козырьком и крыльцом расставляются автоматически
- Окружение: процедурное небо, ползунок «время суток» (солнце двигается, тени, тёплый вечерний свет, отражение неба в глянце), газон, отмостка, дорожка, деревья, мягкая контактная тень
- OrbitControls (палец/мышь), автоповорот, сброс вида
- Адаптив: десктоп — панель справа; мобильный — сцена сверху, панель снизу

## Архитектура прототипа (как устроено и почему)

Всё состояние — объект `S`. Любое изменение геометрии → `build()` пересобирает группу `house` целиком.
Изменение цвета/покрытия → `applyLook()` меняет материалы без пересборки. При переключении металлочерепицы и плоских шейдерных профилей заменяется только геометрия скатов.

### Геометрия крыши — `roofModel()`
- Считается в локальных осях: `p` — поперёк короткой стороны, `q` — вдоль длинной. Хелпер `P(p,y,q)` переводит в мировые (конёк всегда вдоль длинной стороны).
- Возвращает `{ slopes, walls, ridges, y0, pitchText }`: скаты как полигоны (массив Vector3), фронтоны, линии конька/рёбер, высоту карниза.
- `y0 = H − O·tan(α)` — плоскость ската проходит ровно через верх стены, свес опускает карниз.
- Крыша поднимается на 4 см над стенами (`lift`) — убирает z-fighting на стыке.
- У односкатной низкий карниз развёрнут к камере (`P0(-p, …)`).
- Ломаная: нижний крутой скат β = min(75°, α+35°), верхний — α.

### Скат — `slopeGeometry(pts)` (ключевая идея)
- Нормаль по Ньюэллу, разворот вверх.
- Для каждого ската своя система осей: `U` — горизонталь вдоль карниза, `V` — вверх по линии стока, `n = U × V`.
- Вершинные атрибуты `slopeU`, `slopeV`, `aM` (координаты в метрах в плоскости ската от нижней точки).
- Благодаря этому **волна/фальц на любом скате всегда идёт по линии стока**, на треугольных вальмах тоже.

### Шейдер профиля листа — `roofMat.onBeforeCompile`
- `MeshPhysicalMaterial` + инъекция GLSL: функции высоты `hTile` / `hProf` / `hFalz` от `aM` (метры).
- Нормаль возмущается конечными разностями высоты вдоль `slopeU`/`slopeV`; впадины чуть затемняются.
- `detailFade()` гасит рельеф по `fwidth` вдали — против муара. `uPer` у фальца занижен (0.12), иначе узкие рёбра алиасятся.
- Цвет — обычный `material.color` → любой RAL без текстур.
- Черепица (Монтеррей, Каскад, Бавария): затенение волны гаснет только при шаге волны в несколько пикселей и не зависит от видимости поперечной ступеньки. У профнастила и фальца порог строже — острые грани дают муар. У профнастила (С21, НС35) наклон грани для нормали усредняется по размеру пикселя (`e` от `fwidth(vM)`), иначе на расстоянии 10–15 м по скату идут дуги муара.
- Впадины профиля получают меньше отражения неба и рассеянного света (`aomap_fragment`, по `hgt(vM)`): на тёмных RAL волна читается именно за счёт бликов на гребнях.

### Объёмная металлочерепица
- `tileHeight(u,v)` задаёт высоту профиля в метрах; соответствует `hTile` в GLSL.
- `roofReliefGeometry(s,material,quality)` строит объёмную сетку для Монтеррея, Каскада, Баварии, С21 и НС35 (фальц — плоский скат с шейдером). Профили приближённые, не сертифицированные.
- Для черепичных профилей (Монтеррей, Каскад, Бавария) уровень `overview`: до 32 000 треугольников на скат, `detail`: до 96 000. Профнастил от уровня не зависит. Детализация повышается при приближении и в ракурсе «Кровля», снижается при удалении; используется гистерезис.
- Во время изменения размеров создаётся облегчённая сетка; после завершения ползунка уровень уточняется.
- В неподвижной сцене `renderer.render()` не вызывается; OrbitControls продолжает проверяться для затухания движения.
- Для ломаной крыши свес ограничен так, чтобы карниз оставался не ниже 1.8 м. `roofModel()` возвращает `effectiveOverhang` и `maxOverhang`; UI синхронизирует ползунок и объясняет ограничение.

### Доборка и детали в `build()`
- Рёбра скатов считаются через карту `edgeCount`: общее ребро двух скатов — конёк/ребро; горизонтальное на высоте `y0` — карниз (желоб, капельник); наклонное и не общее — торцевая планка.
- `spanAt(slope, v)` — ширина ската на высоте `v` в его плоскости. Используется для снегозадержателей и мансардных окон.
- `orientedBox(lx,ly,lz, X, Y, center)` — бокс в произвольном базисе (ось X, «верх» Y, Z = X×Y). Для деталей в плоскости ската: `X = U`, `Y = n` → Z = −V.
- `rod(a, b, r)` — цилиндр между двумя точками.

### Фасад — `wallMat.onBeforeCompile`
- Узор по мировым координатам (`vWP`, `vWN`): штукатурка / кирпич 26×7.5 / блок 40×20, перевязка рядов, вариация цвета по hash, затемнение у земли (фейковый AO).

### Небо и свет — `setTime(h, withEnv)`
- Сфера-небо на `ShaderMaterial` (зенит/горизонт/земля/солнце), следует за камерой.
- Окружение для отражений: `PMREMGenerator.fromScene(envScene)` — перегенерируется только по `change` ползунка (дорого), по `input` двигается лишь свет.

### Остатки
- Объект `kit` (метражи) ещё считается в `build()`, но в UI не выводится — можно удалить при переносе.

## Известные ограничения
- План дома только прямоугольный (нет Г/Т-образных, нет ендов).
- Шатровая на вытянутом доме — торцевые скаты положе боковых.
- Окна в стенах расставляются автоматически.
- Нет SSAO (только фейковый: тень-текстура под домом + затемнение стен у земли).
- Профили упрощённые (не точная геометрия конкретных моделей).
- Много отдельных мешей (~200–400 draw calls) — на слабых телефонах стоит перейти на InstancedMesh / merge.
- В опубликованном артефакте нельзя скачать скриншот (песочница). В своём проекте — можно.

## Дорожная карта (только визуал), по приоритету
1. Перенос в Next.js + React Three Fiber (см. ниже), функционал 1-в-1.
2. Перетаскивание мансардных окон по скату — реализовано в прототипе.
3. Дымоход: бокс на скате, планки примыкания, перетаскивание как у окон.
4. Режим «до/после»: две камеры / split-screen, два цвета или материала рядом.
5. Пресеты домов: «Дом 8×10», «С мансардой», «Гараж», «Навес».
6. Точные профили: Монтеррей, Каскад, Бавария (есть, по чертежу: 1135/1020 мм, 4 волны по 255 мм, волна 30 мм, ступень 30 мм, склоны R60; константы сечения — `bavariaSection()`, общие для сетки и шейдера), Супермонтеррей, С8/С21/НС35 — по реальным размерам волны.
7. Г- и Т-образный план: straight skeleton (npm-пакеты есть) → ендовы, сложные вальмы.
8. White-label (логотип/цвета продавца). Экспорт PNG и ссылка на конфигурацию с камерой уже реализованы.
9. Производительность: InstancedMesh для кронштейнов/хомутов, merge статичной доборки, адаптивный DPR.

## Перенос в Next.js (стек владельца: Next.js, TypeScript, Vercel)

```
app/
  page.tsx                  // layout: <Viewer/> + <Panel/>
components/
  viewer/Viewer.tsx         // <Canvas shadows>, камера, OrbitControls (drei)
  viewer/Sky.tsx            // небо + PMREM окружение + солнце
  viewer/House.tsx          // стены, цоколь, окна, дверь
  viewer/Roof.tsx           // скаты из roofModel()
  viewer/RoofTrims.tsx      // коньки, планки, снегозадержатели
  viewer/Gutters.tsx        // водосток
  viewer/Skylights.tsx      // мансардные окна
  viewer/Environment.tsx    // газон, деревья, дорожка
  panel/*.tsx               // секции UI
lib/
  state.ts                  // zustand store = объект S
  catalog.ts                // TYPES, MATS, COATS, RAL, FACADE, PLINTH, GUTTER, FRAMES
  geometry/roofModel.ts     // чистые функции, без React — переносить как есть
  geometry/slope.ts         // slopeGeometry, spanAt, newell
  materials/roofMaterial.ts // onBeforeCompile профиля
  materials/wallMaterial.ts
```

Правила переноса:
- Геометрию держать в чистых TS-функциях (`lib/geometry`) и покрыть unit-тестами (vitest): площадь, ориентация U/V, `spanAt`, количество скатов по типу.
- Геометрию мемоизировать через `useMemo` по нужным полям стора, а не пересобирать всю сцену на каждый ползунок.
- Материалы — по одному экземпляру, цвет менять через ref (не пересоздавать — иначе перекомпиляция шейдеров).
- `customProgramCacheKey` у материалов с `onBeforeCompile` оставить.
- Canvas грузить через `dynamic(() => import(...), { ssr:false })`.

## Как проверять визуально
- Локально: `npx serve prototype` или `npm run dev` → смотреть в браузере, крутить все 5 форм.
- Headless-скриншоты в Chrome со SwiftShader иногда дают пустой canvas — это артефакт headless, не баг. Надёжный способ: `preserveDrawingBuffer:true` + `canvas.toDataURL()` в консоль, либо Playwright с реальным GPU.
- Чек-лист после правок: все 5 форм × 3 материала; W>L и W<L (оси меняются местами); угол 10° и 55°; свес 0.2 и 0.9; мобильная ширина 390px.
